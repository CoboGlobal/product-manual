Cobo Portal Mobile (hereinafter referred to as Portal Mobile, shown in the app as **Cobo Portal App**) is the next-generation replacement for Cobo Guard. Accounts bound to Cobo Guard can migrate to Portal Mobile by following this guide. After migration, identity verification, approvals, transactions, and key share management for the account are handled by Portal Mobile.

<Warning>
**Read before you start:**

- **Migration is per account.** If the original Cobo Guard was bound to multiple accounts, sign in to Portal Mobile with each account and migrate it separately.
- **Cobo Guard stops working for the account after migration.** Future approvals and transactions can only be handled in Portal Mobile.
- **Do not uninstall Cobo Guard before migration finishes.** You may still need it to restore key shares or create a new backup.
- **If migration generates a new key share, the old key share and all of its backup files become invalid.** Back up the new key share immediately at the end of migration.
</Warning>

<Info>
Cobo Portal Mobile and Cobo Guard are **two separate products**, not different versions of the same product. For a comparison of feature scope and core identifiers, refer to [Introduction to Cobo Portal Mobile](/en/portal-mobile/introduction#product-distinction-for-search-reference).
</Info>

## Before you start

Check each of the following before starting migration:

| Item | Details |
| --- | --- |
| Install Portal Mobile | Install the latest Portal Mobile on the phone you will use long-term. See [Download Cobo Portal Mobile](/en/portal-mobile/download). This phone becomes the account's trusted device. |
| Device security | The phone must have a screen lock enabled and must not be jailbroken / rooted or an emulator. Enabling Face ID or fingerprint is recommended. |
| Keep Cobo Guard | Keep Cobo Guard installed until migration is fully complete. |
| Backup file of the original key share | If the account already has key shares, prepare the backup file created in Cobo Guard, either: a **backup on iCloud / Google Drive** (signed in with the same cloud account used for the backup, with the file still in the cloud), or a **local backup file** (JSON, saved on this phone in advance). |
| Recovery passphrase | The passphrase you set when creating that backup. |
| Original TSS Node ID (for checking) | Find it in **Cobo Guard > Menu > My TSS Node ID** and note it down. Portal Mobile displays and checks it automatically; you do not need to type it. |
| Other key share holders | If your key share group has other members, ask them in advance to stay online during migration (see [What other key share holders need to do](#other-holders)). |
| Network and time | A stable network and about 10–15 minutes. Do not switch to other apps or lock the screen during migration. |

<Note>**No backup file, or forgot the passphrase?** Open Cobo Guard first, create a new key share backup with a new passphrase, then return to Portal Mobile to continue.</Note>

## Your migration path

Portal Mobile picks the migration path automatically based on your account; you do not choose it. Knowing the path helps you prepare:

| Path | When it applies | What you do |
| --- | --- | --- |
| **Path A: Bind directly** | The account has no key shares in the current environment | Confirm migration → set as trusted device. No backup file needed. |
| **Path B: Restore original shares** | The account has key shares, and the original TSS Node is used only by this account | Confirm migration → restore the original key share → set as trusted device. The TSS Node ID stays the same and the original backup remains valid. |
| **Path C: Regenerate shares** | The account has key shares, and the original TSS Node is also used by other accounts | Confirm migration → restore the original key share → a new TSS Node is created and key shares are regenerated automatically → back up the new key share immediately. The old key share and all backups become invalid. |

## Step 1: Sign in to Portal Mobile

1. Open Portal Mobile and complete the device security setup if prompted (for example, if no screen lock is set).
2. Sign in with **the account bound to Cobo Guard**, using the same sign-in method as Cobo Portal on the web. See [Sign in to Cobo Portal Mobile](/en/portal-mobile/register-and-sign-in).
3. Select your organization and complete identity verification (MFA) when prompted.

After sign-in, Portal Mobile detects that the account is bound to Cobo Guard and opens the **Migrate to Cobo Portal App** page automatically.

## Step 2: Confirm migration

On the **Migrate to Cobo Portal App** page:

1. Review the page:
   - Direction: **Cobo Guard (Current app)** → **Cobo Portal App (Migrate to)**.
   - Notice **Cobo Guard will stop working after migration**: future approvals and transactions for this account will be handled in Cobo Portal App.
2. Tap **Confirm migration**. Portal Mobile runs a preflight check first.
   - Check passes: continue to the next step. Path A goes straight to [Step 4](#complete-migration).
   - **No migratable TSS Node was found for this account.**, **Migration preflight failed. Please try again.**, or another error: see [Troubleshooting](#troubleshooting).

<Note>If you do not want to migrate yet, tap **Not now**. Portal Mobile signs you out; you can keep using Cobo Guard and sign in to Portal Mobile again later to start over. Until migration is complete, an account bound to Cobo Guard cannot use other Portal Mobile features.</Note>

## Step 3: Restore the original key share

<Note>Only Path B and Path C include this step.</Note>

### 3.1 Confirm preparation

The page shows **Migrate key shares**, explaining that key shares must be restored to this device first:

1. Make sure you have the **Backup file** and the **Recovery passphrase**.
2. Check that the displayed **TSS Node ID on the original Cobo Guard** matches the one in **Cobo Guard > Menu > My TSS Node ID**.
3. Tap **Start restoring shares**.

<Note>If you have no backup file or forgot the passphrase, tap **Open Cobo Guard to re-backup**, complete a new backup in Cobo Guard, then return to Portal Mobile and tap **Start restoring shares**. If Cobo Guard does not open automatically, open it manually.</Note>

### 3.2 Choose where the backup is stored

On the **Restore from backup file** page, choose the backup location:

- **iCloud** (iOS): the backup is fetched from iCloud automatically. If **Cloud Unavailable** appears, check that this phone is signed in to iCloud, Cobo Guard sync is enabled in iCloud settings, iCloud has at least 1 MB free, and iCloud Drive is enabled.
- **Google Drive** (Android): tap **Continue** in the **Use Google Drive** dialog, sign in to your Google account, and **allow access to Google Drive** on the permission screen. Without Drive access, the backup cannot be read.
- **Local File**: select the JSON backup file exported from Cobo Guard on this phone.

### 3.3 Select the TSS Node ID (cloud backups only)

For iCloud or Google Drive, Portal Mobile lists only backups that match the account's original TSS Node ID; if there is exactly one, it is selected automatically. Tap **Continue**.

- **No key share files were found in your Cloud account.**: the signed-in cloud account has no matching backup. Make sure you are signed in to the cloud account used for the backup, use a local file instead, or create a new backup in Cobo Guard.

### 3.4 Enter the passphrase

1. On the **Enter passphrase** page, enter the passphrase set when creating the backup and tap **Continue**.
2. Complete Face ID / fingerprint / screen lock verification when prompted.
3. **Restoring. Please do not close the app.** is shown. Stay on this page until **Key share successfully restored** appears.

## Step 4: Complete migration <a id="complete-migration"></a>

Depending on your path, Portal Mobile opens one of the following automatically.

### Path A and Path B: Set as trusted device

1. On the **Confirm trusted device** page, make sure **Current device** is a phone you personally use long-term.
2. Tap **Set as trusted device**. Complete identity verification (MFA) if prompted.
3. **Binding device. Please do not close the app.** is shown. When binding finishes, you land on the home screen and migration is complete.

<Tip>After Path A, the account has no key shares yet. When key shares are generated later, back them up promptly. See [Generate and back up key shares](/en/portal-mobile/generate-and-back-up-key-shares).</Tip>

### Path C: Wait for key share migration

After restoring, Portal Mobile opens the **Migrate key shares** progress page and starts automatically; no action is needed. During this time:

- **Keep the network connected and do not close Portal Mobile, lock the screen, or switch apps.** This takes about 3 minutes.
- **Do not open Cobo Guard** (keep it closed; uninstalling is not required).
- **Ask all other key share holders in the group to stay online** (see below).

The progress page shows these steps in order, each marked done when complete:

1. **Local restore**: the original key share has been restored to this device.
2. **Generate new TSS Node ID**: a new TSS Node is created on this device.
3. **Regenerate key shares · Prod / Dev**: one row per environment that has key shares. Other holders in the group are listed under this step with an **Online / Offline** status.
4. **Bind new device**: this device is bound as the account's trusted device.

When all steps finish, **Migration completed** appears and Step 5 opens automatically. If a step fails, see [If migration fails](#migration-failed).

## Step 5: Back up the new key share

<Note>Only Path C includes this step. It is mandatory and cannot be skipped.</Note>

1. On the **Back up your key share again** page, check the status: **Old key share: Invalidated**, **New key share: Generated**. Tap **Back up now**.
2. Choose a backup method: **iCloud backup**, **Google Drive backup**, or **Local file backup**.
3. Set a new passphrase and enter it again to confirm. It must have at least 16 characters, including at least one capital letter, one number, and one special character.
4. In **Backup Notice**, check both confirmations and tap **Confirm backup**.
5. Complete Face ID / fingerprint / screen lock verification and wait for **Backing up. Please do not close the app.** to finish.
   - For a local file backup, save the file somewhere safe, then tap **I've saved the backup file** in the **Confirm backup completed** dialog.
6. After the backup succeeds, you land on the home screen and migration is complete.

<Warning>You need both the new backup file and the new passphrase. Without a backup of the new key share, your assets cannot be recovered if the phone is lost, damaged, replaced, or the app is uninstalled. The original Cobo Guard backup files are invalid after migration; do not use them to restore.</Warning>

<Note>If you close the app during this step, it may open directly to the home screen when relaunched. In that case, go to **Account** > **Key shares** right away and complete the backup. See [Generate and back up key shares](/en/portal-mobile/generate-and-back-up-key-shares).</Note>

## Step 6: Verify the result

1. Go to **Account** > **Key shares** and confirm the TSS Node ID and key share groups are shown (Path C shows the new TSS Node ID).
2. Go to **Account** > **Test messages** and send a test approval message to confirm Portal Mobile receives approvals.
3. If the original Cobo Guard was bound to other accounts, sign out and repeat Steps 1–6 with the next account.
4. Uninstall Cobo Guard only after every account is migrated and its new backup is confirmed.

## What other key share holders need to do <a id="other-holders"></a>

Path C regenerates key shares for the whole key share group, so **all** holders in the group must be online. Before you start, let them know:

- **Holders using Portal Mobile**: keep Portal Mobile open and online. When a request with status **Pending key share migration** arrives, open the **Key Share Migration** page, check **Migration Account**, **Old Node ID**, and **New Node ID**, then tap **Start**.
- **Holders using Cobo Guard**: open Cobo Guard and keep it online.
- **Server TSS nodes (API type)**: make sure the server TSS node is running.

The migrating user can see each holder's **Online / Offline** status on the progress page. If someone is offline, contact them directly.

## If migration fails <a id="migration-failed"></a>

### A step fails on the progress page (Path C)

The failed step is marked red, with a **Failure reason** and **What to do**:

1. Make sure the network is stable and all other holders are online.
2. Make sure the original TSS Node has the latest backup.
3. Tap **Retry** next to the failed step.

Retry continues from the failed step; completed steps are kept. Regenerating key shares for each environment is atomic: a failure rolls back the whole step and never leaves partial key shares.

| Failure reason | What to do |
| --- | --- |
| **Timed out. Please try again.** | Usually a holder is offline or the network is unstable. Make sure everyone is online, then tap **Retry**. |
| **The original Guard TSS node is missing key shares. Open Cobo Guard and back up again.** | On the key share regeneration step, tap **Log out**, create a new backup in Cobo Guard, then start again from Step 1. |
| **Migration state is missing. Please start again.** | Log out and start again from Step 1. |
| **Migration failed. Please try again.** or any other reason | Tap **Retry**. If it keeps failing, contact support with a screenshot of the failure reason. |

<Note>When a key share regeneration step fails, the progress page offers **Log out**. Logging out clears the original key share restored on this device, so you will need to restore again from Step 3. When the bind step fails, only **Retry** is available; do not uninstall Portal Mobile.</Note>

### The app was closed during migration

- **Path C**: migration progress is saved on this device. Reopen Portal Mobile and sign in with the same account; it returns to the progress page and continues the remaining steps. Do not uninstall Portal Mobile, or you will have to start over.
- **Path A / B**: reopen Portal Mobile and start again from Step 2.

## Troubleshooting <a id="troubleshooting"></a>

| Message or symptom | Cause and fix |
| --- | --- |
| **No migratable TSS Node was found for this account.** | The account is not eligible for migration right now. Keep using Cobo Guard and contact support. |
| **Migration preflight failed. Please try again.** | Temporary network or service issue. Tap **Confirm migration** again later. |
| Another error after tapping **Confirm migration** (for example, a migration is already in progress, or the node is shared) | Keep using Cobo Guard, take a screenshot of the message, and contact support. |
| **Incorrect passphrase. Please try again.** | Re-enter the passphrase set for that backup. If you have forgotten it, create a new backup in Cobo Guard. |
| **This backup file is not recognized. Please select a valid JSON backup file.** | The selected file is not a Cobo Guard backup. Select the correct file. |
| **The selected TSS Node ID does not match your account. Please select the correct backup.** | The backup belongs to another account or node. Select the backup whose TSS Node ID matches **Cobo Guard > Menu > My TSS Node ID**. |
| **Unable to open Cobo Guard. Please open it manually to re-backup.** | Open Cobo Guard manually, create a new backup, then return to Portal Mobile. |
| **System error. Please try again.** | Try again later. If it persists, contact support. |

## After migration

- Cobo Guard no longer works for the account. Approvals and transactions are handled in Portal Mobile, organized by account + organization. For multiple accounts, switch accounts and sign in again.
- After migration, you can also withdraw, transfer, and view transaction history in Portal Mobile.
- After Path C, the old key share and its backup files are invalid; use only the new backup created in Step 5.
- Accounts never bound to Cobo Guard do not need to migrate. See [Set up Cobo Portal Mobile](/en/portal-mobile/set-up).

If you have questions about migration, please [contact support](mailto:help@cobo.com).
