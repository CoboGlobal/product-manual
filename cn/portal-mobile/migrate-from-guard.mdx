Cobo Portal Mobile（以下简称 Portal Mobile，应用内显示为 **Cobo Portal App**）是 Cobo Guard 的下一代替代产品。已绑定 Cobo Guard 的账户，可以在 Portal Mobile 中按本文档完成迁移。迁移完成后，该账户的身份验证、审批、交易与私钥分片管理都改由 Portal Mobile 承担。

<Warning>
**开始前请先阅读：**

- **迁移按账户进行。** 如果原 Cobo Guard 绑定了多个账户，需要用每个账户分别登录 Portal Mobile 并各自完成迁移。
- **迁移完成后，该账户的 Cobo Guard 不再生效。** 后续审批与交易只能在 Portal Mobile 中处理。
- **迁移完成前请勿卸载 Cobo Guard。** 恢复私钥分片或重新备份时可能仍需用到它。
- **如果迁移生成了新的私钥分片，原私钥分片及其备份文件将全部失效。** 请务必在迁移结束时立即备份新的私钥分片。
</Warning>

<Info>
Cobo Portal Mobile 与 Cobo Guard 是**两款独立的产品**，并非同一产品的不同版本。有关两款产品的功能边界与核心标识符对比，请参阅 [Cobo Portal Mobile 简介](/cn/portal-mobile/introduction#product-distinction)。
</Info>

## 迁移前准备

开始迁移前，请逐项确认以下条件：

| 准备项 | 说明 |
| --- | --- |
| 安装 Portal Mobile | 在要长期使用的手机上安装最新版 Portal Mobile，参阅[下载 Cobo Portal Mobile](/cn/portal-mobile/download)。该手机将成为账户的可信设备。 |
| 设备安全 | 手机需开启锁屏密码，且未越狱 / Root、不是模拟器。建议同时开启 Face ID 或指纹。 |
| 保留 Cobo Guard | Cobo Guard 保持已安装状态，直到迁移全部完成。 |
| 原私钥分片的备份文件 | 如果账户已生成过私钥分片，需准备 Cobo Guard 中创建的备份文件，二选一：**iCloud / Google Drive 上的备份**（需登录备份时使用的同一个云账户，且文件仍在云盘中）或**本地备份文件**（JSON 格式，需提前保存到这台手机上）。 |
| 恢复口令 | 创建上述备份时设置的恢复口令（passphrase）。 |
| 原 TSS Node ID（核对用） | 在 **Cobo Guard > 菜单 > 我的 TSS Node ID** 查看并记下。迁移时 Portal Mobile 会自动显示并核对，无需手动输入。 |
| 其他私钥分片持有者 | 如果您所在的私钥分片组还有其他成员，请提前通知他们在迁移期间保持在线（详见[其他私钥分片持有者需要做什么](#other-holders)）。 |
| 网络与时间 | 稳定的网络，预留约 10–15 分钟，迁移过程中不要切换到其他应用或锁屏。 |

<Note>**没有备份文件，或忘记了恢复口令？** 请先打开 Cobo Guard，重新创建一份私钥分片备份并设置新的恢复口令，然后再回到 Portal Mobile 继续迁移。</Note>

## 了解您的迁移路径

Portal Mobile 会根据账户情况自动选择迁移路径，您无需手动选择。了解路径有助于预估需要准备的内容：

| 路径 | 适用情况 | 需要做的事 |
| --- | --- | --- |
| **路径 A：直接绑定** | 账户在当前环境下尚未生成私钥分片 | 确认迁移 → 设为可信设备。无需备份文件。 |
| **路径 B：恢复原分片** | 账户已有私钥分片，且原 TSS Node 只被本账户使用 | 确认迁移 → 恢复原私钥分片 → 设为可信设备。TSS Node ID 保持不变，原备份仍然有效。 |
| **路径 C：重新生成分片** | 账户已有私钥分片，且原 TSS Node 同时被其他账户使用 | 确认迁移 → 恢复原私钥分片 → 自动生成新 TSS Node 并重新生成私钥分片 → 立即备份新私钥分片。原私钥分片及备份全部失效。 |

## 第 1 步：登录 Portal Mobile

1. 打开 Portal Mobile，按提示完成设备安全设置（如尚未开启锁屏密码）。
2. 使用**已绑定 Cobo Guard 的账户**登录，登录方式与 Cobo Portal 网页版一致。参阅[登录 Cobo Portal Mobile](/cn/portal-mobile/register-and-sign-in)。
3. 按提示选择组织并完成身份验证（MFA）。

登录后，Portal Mobile 检测到账户当前绑定的是 Cobo Guard，会自动打开**迁移到 Cobo Portal App** 页面。

## 第 2 步：确认迁移

在**迁移到 Cobo Portal App** 页面：

1. 阅读页面信息：
   - 迁移方向：**Cobo Guard（当前 App）** → **Cobo Portal App（迁移到）**。
   - 提示**迁移后 Cobo Guard 将不再生效**：该账户后续的审批消息与交易将统一在 Cobo Portal App 处理。
2. 点击**确认迁移**。Portal Mobile 会先进行迁移前置检查。
   - 检查通过：进入下一步。路径 A 会直接跳到[第 4 步](#complete-migration)。
   - 提示**当前账户没有可迁移的 TSS Node**、**迁移前置检查失败，请重试**或其他错误：请参阅[常见问题与错误处理](#troubleshooting)。

<Note>如果暂时不想迁移，可点击**暂不迁移**。Portal Mobile 会退出登录，您可以继续使用 Cobo Guard，之后再登录 Portal Mobile 重新开始。在完成迁移前，已绑定 Cobo Guard 的账户无法使用 Portal Mobile 的其他功能。</Note>

## 第 3 步：恢复原私钥分片

<Note>仅路径 B 与路径 C 需要此步骤。</Note>

### 3.1 确认准备事项

页面显示**迁移私钥分片**，提示需先将私钥分片恢复到本机：

1. 确认您已准备好**备份文件**与**恢复口令 passphrase**。
2. 核对页面显示的**原 Cobo Guard 上的 TSS Node ID**，与 **Cobo Guard > 菜单 > 我的 TSS Node ID** 中显示的一致。
3. 点击**开始恢复分片**。

<Note>如果此时没有备份文件或忘记了口令，点击**前往 Cobo Guard 重新备份**，在 Cobo Guard 中完成新的备份后，回到 Portal Mobile 点击**开始恢复分片**。如果无法自动跳转，请手动打开 Cobo Guard。</Note>

### 3.2 选择备份文件的存储位置

在**从备份文件恢复**页面，选择备份文件所在位置：

- **iCloud**（iOS）：自动读取 iCloud 中的备份。如果提示**云存储不可用**，请检查：手机已登录 iCloud；iCloud 设置中已开启 Cobo Guard 的同步权限；iCloud 至少有 1 MB 可用空间；iCloud 云盘已开启。
- **Google Drive**（Android）：在**使用 Google Drive** 弹窗点击**继续**，登录 Google 账户，并在授权页**勾选允许访问 Google Drive**。未授权 Drive 将无法读取备份。
- **本地文件**：从手机文件中选择 Cobo Guard 导出的 JSON 备份文件。

### 3.3 选择 TSS Node ID（仅云端备份）

选择 iCloud 或 Google Drive 后，Portal Mobile 只会列出与本账户原 TSS Node ID 一致的备份；如果只有一个，会被自动选中。确认后点击**继续**。

- 提示**当前账户云盘内暂未发现可以恢复的私钥分片文件**：说明当前云账户中没有匹配的备份。请确认登录的是备份时使用的云账户，或改用本地文件，或回到 Cobo Guard 重新备份。

### 3.4 输入恢复口令

1. 在**输入恢复口令**页面，输入创建备份时设置的恢复口令，点击**继续**。
2. 按系统提示完成 Face ID / 指纹 / 锁屏密码验证。
3. 页面显示**恢复中，请勿关闭应用**。请保持在当前页面，直到看到**私钥分片恢复成功**。

## 第 4 步：完成迁移 <a id="complete-migration"></a>

根据迁移路径，Portal Mobile 会自动进入以下页面之一。

### 路径 A 与路径 B：设为可信设备

1. 在**确认可信设备**页面，确认**当前设备**是您本人长期使用的手机。
2. 点击**设为可信设备**。如有提示，完成身份验证（MFA）。
3. 页面显示**设备绑定中，请勿关闭app**。绑定完成后自动进入首页，迁移完成。

<Tip>路径 A 迁移完成后，账户还没有私钥分片。后续生成私钥分片时请及时备份，参阅[生成并备份私钥分片](/cn/portal-mobile/generate-and-back-up-key-shares)。</Tip>

### 路径 C：等待私钥分片迁移

恢复成功后，Portal Mobile 自动进入**迁移私钥分片**进度页并开始执行，无需操作。期间请务必：

- **保持网络通畅，不要关闭 Portal Mobile、不要锁屏、不要切到其他应用。** 整个过程预计约 3 分钟。
- **不要打开 Cobo Guard**（保持关闭即可，无需卸载）。
- **请组内其他私钥分片持有者保持在线**（见下文）。

进度页会依次显示以下步骤，每完成一步显示为已完成：

1. **本地恢复**：原私钥分片已恢复到本机。
2. **生成新 TSS Node ID**：为本机生成新的 TSS Node。
3. **重新生成私钥分片 · Prod 环境 / Dev 环境**：每个有私钥分片的环境各一行。此步骤下方会列出组内其他持有者及其**在线 / 离线**状态。
4. **绑定新设备**：将本机绑定为账户的可信设备。

全部完成后显示**迁移完成**，并自动进入第 5 步。如果某一步失败，请参阅[迁移失败怎么办](#migration-failed)。

## 第 5 步：备份新私钥分片

<Note>仅路径 C 需要此步骤，且必须完成，无法跳过。</Note>

1. 在**请重新备份私钥分片**页面，确认状态：**原私钥分片：已失效**，**新私钥分片：已生成**。点击**立即备份**。
2. 选择备份方式：**iCloud 备份**、**Google Drive 备份**或**本地文件备份**。
3. 设置新的恢复口令并再次输入确认。口令需至少 16 个字符，包含至少一个大写字母、一个数字和一个特殊字符。
4. 在**备份须知**中勾选两项确认，点击**确认备份**。
5. 完成 Face ID / 指纹 / 锁屏密码验证，等待**备份中，请勿关闭应用**结束。
   - 如果选择本地文件备份，请把文件保存到安全位置，然后在**确认完成备份**弹窗点击**我已保存好备份文件**。
6. 备份成功后自动进入首页，迁移完成。

<Warning>新私钥分片的备份文件和新恢复口令缺一不可。不备份新私钥分片，一旦手机丢失、损坏、更换或卸载 App，资产将无法恢复。原 Cobo Guard 的备份文件在迁移后已失效，请勿再用于恢复。</Warning>

<Note>如果在本步骤中途关闭了应用，重新打开后可能直接进入首页。此时请立即前往**账户** > **私钥分片**完成备份，参阅[生成并备份私钥分片](/cn/portal-mobile/generate-and-back-up-key-shares#备份私钥分片)。</Note>

## 第 6 步：确认迁移结果

1. 前往**账户** > **私钥分片**，确认可以看到 TSS Node ID 与私钥分片组信息（路径 C 显示的是新的 TSS Node ID）。
2. 前往**账户** > **测试消息**，发送一条测试审批消息，确认 Portal Mobile 能正常收到审批。
3. 如果原 Cobo Guard 还绑定了其他账户，退出登录后用下一个账户重复第 1–6 步。
4. 所有账户都迁移完成且新备份已确认后，才可以卸载 Cobo Guard。

## 其他私钥分片持有者需要做什么 <a id="other-holders"></a>

路径 C 会为整个私钥分片组重新生成分片，需要组内**所有**持有者在线配合。在您开始迁移前，请通知他们：

- **使用 Portal Mobile 的持有者**：保持 Portal Mobile 打开并联网。收到状态为**等待私钥分片迁移**的请求后，进入**私钥分片迁移**页面，核对**迁移账号**、**旧 Node ID** 与**新 Node ID**，点击**开始**。
- **使用 Cobo Guard 的持有者**：打开 Cobo Guard 并保持联网。
- **服务器端 TSS 节点（API 类型）**：确保服务器 TSS 节点处于运行状态。

迁移方可以在进度页查看每位持有者的**在线 / 离线**状态。出现离线时，请直接联系对应持有者。

## 迁移失败怎么办 <a id="migration-failed"></a>

### 进度页某一步失败（路径 C）

失败的步骤会标红，并显示**失败原因**与**如何处理**：

1. 确认网络通畅，组内其他持有者都在线。
2. 确认原 TSS Node 已有最新备份。
3. 点击失败步骤旁的**重试**。

重试会从失败的那一步继续，已完成的步骤不受影响。每个环境的私钥分片重新生成是原子操作：失败会整体回滚，不会产生残缺的分片。

| 失败原因 | 处理方式 |
| --- | --- |
| **等待超时，请重试。** | 通常是有持有者离线或网络不稳定。确认所有持有者在线后点击**重试**。 |
| **原 Guard TSS Node 私钥不全，请前往 Cobo Guard 重新备份。** | 在私钥分片重新生成步骤点击**退出登录**，打开 Cobo Guard 重新备份，再从第 1 步重新开始。 |
| **缺少迁移状态，请重新开始。** | 退出登录后从第 1 步重新开始。 |
| **迁移失败，请重试。**或其他原因 | 点击**重试**。多次失败请联系客服，并提供页面显示的失败原因截图。 |

<Note>在私钥分片重新生成步骤失败时，进度页会提供**退出登录**。退出登录会清除本机上已恢复的原私钥分片，下次需从第 3 步重新恢复。绑定新设备步骤失败时只能**重试**，请勿卸载 Portal Mobile。</Note>

### 迁移中途关闭了应用

- **路径 C**：迁移进度会保存在本机。重新打开 Portal Mobile 并登录同一账户后，会自动回到进度页继续剩余步骤。请勿卸载 Portal Mobile，否则需重新开始。
- **路径 A / B**：重新打开 Portal Mobile 后，从第 2 步重新开始即可。

## 常见问题与错误处理 <a id="troubleshooting"></a>

| 现象或提示 | 原因与处理 |
| --- | --- |
| **当前账户没有可迁移的 TSS Node。** | 账户当前不符合迁移条件。请继续使用 Cobo Guard，并联系客服。 |
| **迁移前置检查失败，请重试。** | 网络或服务暂时异常。稍后再次点击**确认迁移**。 |
| 点击**确认迁移**后显示其他错误提示（如迁移已在进行中、节点被其他账户共享等） | 请继续使用 Cobo Guard，截图提示内容并联系客服。 |
| **恢复口令错误，请重试。** | 重新输入创建该备份时设置的口令。确实忘记口令时，回到 Cobo Guard 重新备份。 |
| **无法识别该备份文件，请选择正确的备份文件，格式为 JSON。** | 选择的不是 Cobo Guard 导出的备份文件，请重新选择。 |
| **所选的 TSS Node ID 非当前账户绑定的 TSS Node ID，请重新选择。** | 选择的备份属于其他账户或其他节点。请选择 TSS Node ID 与 **Cobo Guard > 菜单 > 我的 TSS Node ID** 一致的备份。 |
| **无法打开 Cobo Guard，请手动打开后重新备份。** | 手动打开 Cobo Guard 完成重新备份，再回到 Portal Mobile。 |
| **系统错误，请重试。** | 稍后重试；多次出现请联系客服。 |

## 迁移完成后

- 该账户的 Cobo Guard 不再生效，审批消息与交易统一在 Portal Mobile 中处理，并按「账户 + 组织」区分。多账户需要切换账户重新登录。
- 迁移后，您还可以在 Portal Mobile 上发起提币、转账并查看交易记录。
- 路径 C 迁移后，原私钥分片及其备份文件已失效，请只使用第 5 步创建的新备份。
- 从未绑定 Cobo Guard 的账户无需迁移，请参阅[设置 Cobo Portal Mobile](/cn/portal-mobile/set-up)。

如对迁移有疑问，请[联系客服](mailto:help@cobo.com)获取帮助。
