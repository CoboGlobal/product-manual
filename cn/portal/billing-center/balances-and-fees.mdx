## Credits 与 Gas 代币

| | Credits | Gas 代币 |
|---|---|---|
| 充值方式 | USDT、USDC 或 USD | 按链充入该链用于支付手续费的币 |
| 可支付 | 任意受支持公链的手续费、Cobo 月度账单、增购的套餐额度 | **仅所在链的手续费** |
| 不可支付 | — | Cobo 账单 |

## 一笔手续费按什么顺序扣

Cobo 按顺序查看三个来源：

1. **钱包地址自己持有的 Gas 代币**
2. **费用中心里的 Gas 代币**
3. **Credits**

三个都不够，交易失败。

第 1 步会不会被跳过，取决于您选的代付规则；第 2 步需要先开启 Gas 代币充值，未开启时直接进入第 3 步。

### 一笔手续费只由一个来源全额支付

<Warning>
**某个来源不够时，是整笔换下一个来源支付，而不是用下一个来源补上差额。**

举例：地址里有 0.003 ETH，这笔交易需要 0.005 ETH。费用中心不会补那 0.002，而是**将 0.005 全额支付**，地址里原有的 0.003 分文未动。

同理，费用中心的 Gas 代币不足时，整笔手续费改由 Credits 支付，不会先扣掉 Gas 代币余额再用 Credits 支付剩余部分。
</Warning>

这一点直接影响对账：您在交易记录里看到的每一笔手续费，**只会标记一个支付来源**——「Credits 支付」或「Gas 代币支付」。

## Portal 页面与 API 是两套规则

<Warning>
**「各链代付规则」与「代付时从哪种余额扣费」这两项设置，只对通过 API 发起的交易生效。通过 Portal 页面发起的转账不读取这些配置。**
</Warning>

### Portal 页面发起的转账

行为按链固定，不受上述设置影响：

| 链 | 固定行为 |
|---|---|
| EVM 兼容链 | 地址内的 Gas 代币足够时用地址的；不足时整笔由费用中心支付 |
| TRON、Solana、Tempo | 直接由费用中心支付 |

此外，Portal 转账走费用中心时，Gas 代币不足会**一律改用 Credits 支付**。

如果某笔 Portal 转账不希望由费用中心代付，请在发起转账时的弹窗中单独选择。

### 通过 API 发起的交易

交易如何支付手续费，由请求中的 `auto_fuel` 参数决定。**该参数不传时默认为 `UsePortalPreference`，即沿用设置页中配置的各链代付规则**；显式传入其他取值时，由请求自行指定，不读取页面配置。

<Note>该参数的全部取值与请求示例，请参考 Developer Hub 的[转账接口文档](https://www.cobo.com/developers/v2/api-references/transactions/transfer-token)。</Note>
